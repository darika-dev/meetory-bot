# Meetory UX v1

## Концепция

Meetory — Telegram-бот для сохранения мероприятий в общие Google Calendars.

Особенности:

- мероприятия не хранятся в базе данных Meetory;
- единственный источник истины — Google Calendar;
- пользователь может состоять в нескольких календарях;
- один календарь может принадлежать нескольким людям;
- по умолчанию новое мероприятие сохраняется в активный календарь.

---

# Основные сущности

## Пользователь

Telegram пользователь.

Может:

- иметь несколько календарей;
- создавать календари;
- вступать в календари по приглашению.

---

## Календарь

Общий Google Calendar.

Примеры:

- Meetory Family
- Armenian Week
- Work Trip
- Weekend Plans

Каждый календарь имеет:

- владельца (Owner)
- участников (Members)

Google Calendar — источник истины для текущего названия, описания, часового пояса, событий, Google ACL и фактических прав доступа. Meetory хранит в PostgreSQL только registry-запись календаря и внутреннюю связь Telegram-пользователей с календарём; локальное имя календаря, если оно есть, считается legacy cache.

---

## Роли

### Owner

Может:

- приглашать участников;
- удалять участников;
- переименовывать календарь;
- удалять календарь;
- добавлять мероприятия.

### Member

Может:

- просматривать календарь;
- делать его активным;
- добавлять мероприятия через бота.

# Управление календарями

Команда

```
/calendars
```

показывает только календари Meetory, где пользователь состоит в `calendar_members`.
Названия читаются из Google Calendar API.

```
Ваши календари

[✅ one more]
[📅 first calendar]

[➕ Новый календарь]
```

Нажатие на календарь открывает карточку.

Если календарь активный:

```
📅 one more

Это ваш активный календарь.

[✏️ Переименовать]
[🗑 Удалить]
[🔙 Назад]
```

Если календарь неактивный:

```
📅 first calendar

Что хотите сделать?

[⭐ Сделать активным]
[✏️ Переименовать]
[🗑 Удалить]
[🔙 Назад]
```

## Переключение активного календаря

Пользователь открывает неактивный календарь и нажимает:

```
[⭐ Сделать активным]
```

Meetory проверяет membership и доступность календаря в Google Calendar.
После успеха:

```
✅ Активный календарь изменён.

Текущий календарь:
📅 first calendar
```

## Переименование календаря

Переименовывать календарь может только owner внутри `calendar_members`.

После нажатия:

```
[✏️ Переименовать]
```

Meetory получает актуальное имя из Google Calendar и создаёт `pending_actions` с типом `rename_calendar`.

```
Текущее название:

first calendar

Отправьте новое название календаря.

[✖️ Отмена]
```

Следующее обычное сообщение пользователя используется как новое имя.
Регистр, кириллица, emoji, кавычки и апострофы сохраняются.

После успеха:

```
✅ Календарь переименован.

Новое название:
📅 family plans

[📅 Календари]
[🔙 Назад]
```

## Удаление календаря

Удалять календарь может только owner внутри `calendar_members`.

Первое нажатие показывает подтверждение:

```
⚠️ Удалить календарь «first calendar»?

Это действие нельзя отменить.

Календарь и все его события будут навсегда удалены из Google Calendar.

Участники Meetory потеряют доступ.

[🗑 Удалить навсегда]
[✖️ Отмена]
```

После подтверждения Meetory удаляет secondary calendar через Google Calendar API,
затем очищает registry row и `calendar_members`.

Если удалён активный календарь, Meetory выбирает следующий доступный Meetory calendar как active.
Если календарей больше нет, `active_calendar_id` становится `NULL` и показывается кнопка создания календаря.

# Сохранение мероприятия v1

Пользователь может:

- переслать текстовый анонс;
- отправить обычный текст;
- переслать пост или медиа с подписью.

Meetory пока не делает OCR, не читает PDF, голосовые сообщения и внешние страницы по ссылке.

Если в сообщении нет текста или подписи:

```
Сейчас я умею распознавать только текст мероприятия или подпись к изображению.
```

## AI parsing

Перед распознаванием Meetory выбирает доступный Meetory calendar:

1. берёт `users.active_calendar_id`, если он доступен;
2. иначе выбирает первый доступный календарь пользователя;
3. если календарей нет, предлагает создать календарь;
4. если Google OAuth отозван, предлагает переподключить Google.

Timezone берётся из Google Calendar metadata выбранного календаря.

OpenAI возвращает структурированный результат:

- title;
- date;
- time;
- location;
- description;
- event URL;
- location/map URL;
- source URL;
- schedule type: `single`, `daily_range` или `all_day_range`.

Перед отправкой в OpenAI Meetory добавляет ссылки из Telegram `message.entities` и `caption_entities`: обычные `url` и скрытые `text_link`. Карточные ссылки классифицируются отдельно: конкретная страница мероприятия или билеты идут в `eventUrl`, карты Google/Apple/OSM и похожие ссылки идут в `locationUrl`, агрегатор или канал-источник идут в `sourceUrl`.

Если в объявлении нет времени, но есть диапазон дат, Meetory показывает `all_day_range` и создаёт одно многодневное all-day событие в Google Calendar.
Если объявление описывает диапазон последовательных дат с одинаковыми ежедневными часами, например `31 июля - 2 августа, 18:00-23:00`, Meetory показывает `daily_range` и при сохранении создаёт отдельное событие Google Calendar на каждый день диапазона.

## Event draft

После успешного распознавания:

```
Я нашёл мероприятие:

🎫 Концерт
📅 31 июл. 2026 г.
🕒 19:00
📍 Ереван

Сохранить в:
📅 Meetory Family

[📅 Meetory Family ▾]
[💾 Сохранить]
[✏️ Изменить]
[✖️ Отмена]
```

Для `daily_range`:

```
Я нашёл многодневное мероприятие:

🎫 Большой книжный базар, Лимасол
📅 31 июл. – 2 авг. 2026 г.
🕒 Ежедневно, 18:00–23:00
📍 Лимасол

Будет создано событий: 3.

Сохранить в:
📅 Meetory Family
```

Для `all_day_range`:

```
Я нашёл многодневное мероприятие:

🎫 Музыкальный фестиваль
📅 30 июл. – 1 авг. 2026 г.
🕒 Весь день
📍 Не указано

Сохранить в:
📅 Meetory Family
```

Черновик хранится временно в `pending_actions` с типом `confirm_event`.
Постоянная таблица `events` не создаётся.

## Выбор календаря

Нажатие на календарь в черновике:

```
Выберите календарь:

[✅ Meetory Family]
[📅 Armenian Week]
[🔙 Назад]
```

Выбор календаря влияет только на этот draft и не меняет глобальный active calendar.

## Edit

Нажатие:

```
[✏️ Изменить]
```

показывает:

```
Отправьте исправленную информацию о мероприятии новым сообщением.

Текущий черновик будет заменён.

[✖️ Отменить]
```

Следующее текстовое сообщение снова проходит AI parsing и заменяет draft.

## Save

Нажатие:

```
[💾 Сохранить]
```

атомарно переводит draft в processing, чтобы повторный callback не создал дубль.
После успеха событие создаётся в Google Calendar, а pending draft удаляется.
Для `daily_range` создаётся batch отдельных Google events. Если часть batch не сохранилась, Meetory пытается удалить уже созданные events в рамках текущего запроса; IDs не сохраняются в Neon.
Для `all_day_range` создаётся одно многодневное all-day событие Google Calendar с exclusive `end.date`.

```
✅ Мероприятие сохранено.

🎫 Концерт
📅 31 июл. 2026 г.
📅 Meetory Family

[Открыть в Google Calendar]
[📅 Календари]
```

## Cancel

```
[✖️ Отмена]
```

удаляет pending draft.

```
Черновик мероприятия удалён.
```

# Принципы UX

- Минимум ручного ввода.
- Максимум Inline-кнопок.
- Один активный календарь для сохранения новых событий.
- Просмотр мероприятий всегда по всем календарям пользователя.
- Опасные действия (удаление) требуют подтверждения.
- Все мероприятия физически находятся только в Google Calendar.
- Meetory хранит только пользователей, подключения Google и информацию о календарях.
